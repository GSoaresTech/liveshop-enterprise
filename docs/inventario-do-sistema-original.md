# Inventário das funções do LiveShop Enterprise original

Este documento lista o que o LiveShop Enterprise original faz hoje, função por função, e propõe para cada uma `manter`, `mudar` ou `retirar` no LiveShop B2B. A fonte é o repositório original, `GSoaresTech/liveshop-enterprise`, ramo `main`, commit `8199358`, lido sem nenhuma alteração. Os arquivos do original são só citados, pelo caminho a partir da raiz dele, e nenhum foi copiado para este repositório. **Toda decisão deste documento é uma proposta, escrita com o motivo e a confirmar pelo Tech Lead, salvo as que as respostas das perguntas P1 a P4, dadas em 26/11/2026, já decidiram. Essas estão marcadas "decidida em 26/11/2026" e listadas na seção "Perguntas P1 a P4, respondidas em 26/11/2026".** O que o código ou a documentação do original não permitiu confirmar não virou linha de tabela: virou a pergunta da seção "Dúvidas que o código do original não resolve".

## Como ler

- Cada linha das tabelas tem um número (por exemplo, `4.6`), usado pelas outras seções para apontar para ela.
- **`manter`**: a função continua com a regra que tem no original.
- **`mudar`**: a função continua, mas com regra diferente, por causa de uma mudança de `docs/notes.md`, de uma pergunta em aberto ou de uma decisão do Tech Lead.
- **`retirar`**: a função não entra no B2B.
- **"decidida em 26/11/2026"**: a decisão tem resposta final, dada às perguntas P1 a P4, e a marca diz qual. Quando a resposta decide só uma parte da linha, a marca diz qual parte, e o resto continua "a confirmar pelo Tech Lead".
- A troca do Supabase por API e banco próprios (M1) obriga a reescrever como cada função é feita. Isso não conta como `mudar`. A coluna "Mudança de `docs/notes.md`" marca M1 só onde a função é, ela mesma, uma peça do Supabase: autenticação, regra de acesso no banco, arquivos, fila e agendamento.
- Nas colunas "Onde existe" e "Regra ou ADR", os caminhos são do repositório original. "ADR NNNN" é o arquivo `docs/adr/NNNN-*.md` do original (ADR, do inglês *Architecture Decision Record*, é o registro de uma decisão de arquitetura). "N1-NN" é uma regra inegociável do `CLAUDE.md` do original, §4. "Migration `NNNNNNNNNNNNNN`" é o arquivo `supabase/migrations/NNNNNNNNNNNNNN_*.sql`. "US" seguida de número é uma história do `docs/BACKLOG.md` do original (aberta) ou do `docs/BACKLOG-CONCLUIDO.md` (entregue).
- Os ADRs do original valem só como contexto, conforme `docs/adr/README.md` deste repositório.
- "PDF" é `docs/Enterprise B2B-.pdf` deste repositório, seções 1 a 3, as únicas com conteúdo.

## Termos técnicos do original

| Termo | O que quer dizer |
| --- | --- |
| Supabase | Serviço que o original usa como banco de dados PostgreSQL, autenticação, armazenamento de arquivos e funções de servidor |
| RLS (*Row Level Security*) | Regra dentro do banco que diz quais linhas cada perfil pode ler e escrever. No original, é a única proteção dos dados: não há API própria entre a tela e o banco |
| Policy | Cada regra de RLS, escrita para uma tabela e um perfil |
| Edge Function | Função de servidor do Supabase (código Deno) chamada por HTTP. Roda as regras de negócio sensíveis |
| RPC (*Remote Procedure Call*) | Função escrita dentro do banco e chamada pela aplicação. No original, as que gravam em mais de uma tabela fazem isso numa transação só |
| Migration | Arquivo versionado que muda o banco. O original tem 85 |
| `pg_cron` | Agendador que roda dentro do PostgreSQL |
| `pgmq` | Fila de mensagens que roda dentro do PostgreSQL |
| Motor de notificação | O conjunto de tabela de envio, fila, processador e adaptador de canal que o original usa para enviar mensagens (ADR 0014) |
| JWT (*JSON Web Token*) | Token assinado que identifica a sessão |
| Heartbeat | Sinal que a tela da live envia a cada poucos segundos para dizer que o varejista continua assistindo |
| `service_role` | Credencial do Supabase que ignora a RLS. Só roda dentro de Edge Function |
| UTM | Parâmetro de endereço (`utm_source`) que diz de que campanha ou link veio o acesso |
| Honeypot | Campo escondido no formulário que só um programa automático preenche |
| XLSX | Formato de planilha do Excel |
| Carteira | Varejistas cuja origem é um representante (`varejistas.representante_id`) |
| Link geral | Link de cadastro da indústria sem representante: `/cadastro?industria=<código>` |
| Intenção de compra | Item de um pedido: uma linha por live, combo e varejista, com quantidade e preço do momento |
| Pedido | Cabeçalho que agrupa as intenções de um fechamento, com contato e valor total. Não é venda: o original não tem pagamento (N1-02) |

### P2. A captação pela planilha do Google e pela automação do Unnichat entra neste projeto, ou só o cadastro pelo link do representante?

- **O que o código e os ADRs do original mostram.** O fluxo que roda no original é: landing page externa, automação externa (n8n), planilha `base_de_dados_captacao_b2b`, importação de hora em hora por `importar-leads-planilha` (ADR 0016). Em 11/09/2026, 100% das captações de produção entraram por esse caminho (`CLAUDE.md` §1). O cadastro pelo link (`/cadastro`, linhas 6.1 a 6.3) é "meio alternativo de uso raro". A automação envia o WhatsApp de captação direto pela Unnichat, fora da fila, e isso é uma exceção nominal e datada às regras N1-05 e N1-13, que termina com a campanha (ADR 0018). A importação tem a indústria alvo fixa, em variável de ambiente (`INDUSTRIA_ALVO_CNPJ`). O PDF §2.3 e §3.5 descrevem só o cadastro pelo link do representante.

- **O que mudou no inventário.** As linhas 12.3 e 12.4 passaram de `retirar` para `mudar`: a importação entra, e muda a indústria alvo fixa do original. Como cada indústria indica a sua planilha fica para a E1-03. As linhas 10.2, 10.4 e 10.7 deixaram de depender desta resposta.

### P3. Os dados da Appel Home que estão no Supabase migram para o banco novo? O sistema original continua no ar até este o substituir?

Nada no código obriga a desligar o original.
- **Resposta.** "Não". Os dados da Appel Home não migram para o banco novo.
- **O que mudou no inventário.** Não há épico de migração de dados. As linhas 12.1 e 12.2 (importação em massa de representantes e de varejistas da base legada) continuam `retirar`, a confirmar, e o motivo agora cita a resposta.

## Dúvidas que o código do original não resolve

Cada uma foi encontrada durante a leitura e não tem resposta no código nem nos documentos do original. Nenhuma tem proposta de decisão aqui. O dono de todas é o Tech Lead.

1. **Acesso à live sem cadastro nela.** O produto respondeu, em 14/09/2026, que "apenas alguém cadastrado naquela live possui acesso" (`docs/BACKLOG.md` US0.4.3 do original). O código faz o contrário: `garantir_vinculo_live_atual` (1.4) vincula à live corrente todo varejista ativo da indústria. Por isso a taxa de comparecimento do original pode passar de 100%. Qual regra vale no B2B? Afeta as linhas 1.4 e 10.1.
2. **Produtos e desconto do combo.** O PDF §3.3 lista "produtos inclusos" e "desconto" como dados do combo. O original tem as tabelas `produtos` e `combo_itens` sem nenhuma tela ou função que as use, e a palavra "desconto" não aparece em `src/` nem em `supabase/migrations/`. O combo tem produtos, desconto, os dois ou nenhum? Afeta a linha 5.3 e a E1-03.
3. **Funções do Admin.** O PDF §2.1 lista como permissões do Admin acompanhar todas as lives, as métricas gerais e as analytics. No original o Admin só tem a tela `/admin/usuarios`. O menu do Admin (`src/components/layout/AdminSidebar.tsx`) aponta para `/admin/visao-geral`, rota que não existe em `src/App.tsx`. O Admin do B2B acompanha lives e analytics de todas as indústrias, ou só gerencia usuários? Afeta a seção 2.
4. **Número do suporte por WhatsApp.** O botão de suporte da sala (7.8) tem o número escrito no código (`src/components/lives/SuporteWhatsappLive.tsx`), e o código não diz de quem é. O número é da LiveShop Turbo, da indústria ou de cada live?
5. **Estado do pedido.** O original tem no banco um estado de intenção de compra (`pendente`, `em_negociacao`, `convertida`, `cancelada`) e `pedidos.status`, mas nenhuma tela o muda, e o backlog do original (US0.1.5) o deixa sem ciclo de vida. O B2B precisa que a indústria marque o andamento de cada pedido? Afeta o modelo da E1-03 e as linhas 8.3 e 8.4.
